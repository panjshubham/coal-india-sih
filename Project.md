# ⛏️ CoalGuard / Khanan-Net - Complete Project Deep-Dive & File Analysis

This document is a comprehensive, file-by-file analysis and explanation of the **CoalGuard (Khanan-Net)** platform. It covers everything from the core features and the 10-model AI engine to an exhaustive breakdown of the project structure and what each script, model, and component does.

---

## 1. System Architecture & Features
**CoalGuard** is an offline-first, multi-modal governance and predictive safety platform for the coal mining industry. It ensures DGMS statutory compliance (CMR 2017) and prevents catastrophic accidents using 10 specialized AI models.
- **Frontend**: React 19 PWA (works offline underground).
- **Backend**: Supabase (PostgreSQL) with Row-Level Security and Realtime WebSockets.
- **AI Microservice**: FastAPI Python server executing YOLOv8 (PPE), CLSSA-XGBoost (Water Inrush), Whisper (Voice), and IndicTrans2 (Translation).

## 2. Directory Breakdown & File Analysis

The repository is structured into three main pillars: **AI Service**, **Backend**, and **Frontend**. Below is the detailed analysis of every critical file in the system.

### A. AI & Machine Learning Microservice (`/ai-service`)
This directory contains the Python FastAPI server that runs all 10 AI models.
- **`main.py` (112 KB):** The core heartbeat of the AI engine. It contains the FastAPI endpoints for all AI tasks. It orchestrates the YOLOv8 object detection pipeline for PPE, handles image/audio uploads, triggers the Whisper voice-to-text model, translates regional languages using IndicTrans2, and runs the BART/BERT NLP models to categorize hazard tickets.
- **`water_inrush_model.py` (23 KB):** The hydrochemical modeling script. It implements the cutting-edge **CLSSA-XGBoost** algorithm. It trains and executes the model that predicts underground water floods based on 8 chemical indicators (Calcium, Magnesium, pH, etc.) and generates TreeSHAP explainer values.
- **`water_inrush_model.pkl` & `water_inrush_explainer.pkl`:** The serialized, pre-trained XGBoost model weights and its associated SHAP explainer file. These allow `main.py` to run split-second inference without retraining.
- **`water_inrush_scaler.pkl`:** Feature normalizer for the chemical sensor data.
- **`yolov8n-ppe.pt`:** The pre-trained YOLOv8 Nano PyTorch weights used specifically to https://127.0.0.1:10949/static/artifacts/2269e210-be65-440f-b426-03cf4cc90f01/technical_approach_slide_1790078420031.jpg?csrf=3737dcb9-762a-43b4-b00f-8179aecd003cdetect hardhats, safety vests, and boots in CCTV feeds.
- **`requirements.txt`:** Python dependencies (FastAPI, PyTorch, Transformers, XGBoost, SHAP).

### B. Database & Backend Configuration (`/backend`)
The backend is powered by Supabase (PostgreSQL), and this folder contains all the SQL schemas, migration scripts, and seeding utilities.
- **`schema.sql` (5.5 KB):** The master database schema. It defines the `mines`, `violations`, `inspections`, and `alerts` tables, and sets up PostgreSQL Row-Level Security (RLS).
- **`ppe_vision_migration.sql` (6.9 KB):** Adds the necessary SQL tables to store RTSP camera feeds and logging capabilities for automated PPE violation tickets.
- **`migration_support_tickets.sql`:** Sets up the tables for statutory complaints and hazard tickets generated by workers.
- **`seed_all_demo.js`, `seed_data.js`, `seed_demo_accounts.js`:** Crucial initialization scripts. They pre-populate the database with realistic demo data, including ECL/BCCL subsidiaries, colliery managers, regulators, and dummy violations so the dashboards look alive on the first boot.
- **`seed_audit_ledger.js`:** Seeds the cryptographic `audit_ledger` table with SHA-256 hashed inspection records to prove the immutability of DGMS statutory logs.
- **`camera_monitor.py` (21 KB):** A background Python daemon that simulates or connects to RTSP streams, capturing frames and sending them to the FastAPI YOLOv8 endpoint for continuous worker monitoring.
- **`setup_statutory_schema.js` & `setup_contractors_extension.js`:** Expansion scripts that add tables for third-party mine contractors and specific statutory laws (Mines Act 1952).
- **`/cron` Directory:** Contains scheduled Node.js jobs that automatically escalate unresolved hazards (e.g., escalating from Colliery Manager to Corporate HQ if unresolved for 24 hours).
- **Utility Scripts (`check_*.js`, `fix_*.js`):** A massive suite of over 30 database maintenance and testing scripts (e.g., `check_schema.js`, `fix_identities.js`) used to validate foreign keys, clean up test data, and ensure Supabase Auth identities are correctly linked to user profiles.

The user interface built in React 19, Vite, and Tailwind CSS. It is configured as a Progressive Web App (PWA) to function deep in the mines without cell service.
- **`package.json` & `vite-env.d.ts`:** Dependency lists and TypeScript configurations for Vite.
- **`/src/App.tsx` & `main.tsx`:** The root entry points. Sets up React Router, Supabase Auth context providers, and global layout wrappers.

## 3. The 10 AI Models & How They Work Together

The true power of this project lies in how these files combine into the **10-Model AI Pipeline**:

1. **Worker Reports a Hazard (Offline):** A worker underground opens the PWA (`frontend/src/pages/`). They tap "Voice Note" and speak in Hindi. The PWA saves the audio to `IndexedDB` https://127.0.0.1:10949/static/artifacts/2269e210-be65-440f-b426-03cf4cc90f01/technical_approach_slide_1790078420031.jpg?csrf=3737dcb9-762a-43b4-b00f-8179aecd003c(`frontend/src/services/`).
2. **Auto-Sync:** The worker surfaces. The PWA detects internet and sends the payload to `main.py` in `ai-service`.
3. **Speech-to-Text & Translation:** `main.py` runs **Whisper Large v3** to turn the audio into Hindi text, then runs **IndicTrans2** to translate it to English.
4. **NLP Processing:** The English text is passed through **BART MNLI** to categorize the hazard (e.g., "Roof Support"), and **BERT NER** extracts timestamps and locations.
5. **Database Entry:** The microservice creates a row in the Supabase `violations` table (`backend/schema.sql`).
6. **Real-time Alert:** Supabase WebSockets push the new hazard to the `CollieryDashboard.tsx`, immediately alerting the manager.
